O que é JWT?

Um JSON Web Token é como um crachá assinado. Qualquer um pode ler o que está escrito; só quem tem o secret consegue provar que o crachá não foi adulterado.

header.payload.signature
  • Header

    Metadados: algoritmo (HS256) e tipo (JWT).

  • Payload

    As claims — dados como sub (quem é) e exp (quando expira). São legíveis, não criptografadas.

  • Signature

    Prova de integridade. Com HS256, é um HMAC do header + payload usando o secret. Se alguém mudar uma vírgula, a assinatura quebra.

Assinar

O servidor cria o token com as claims e o secret.

Verificar

Na próxima requisição, confere assinatura, header (alg/typ) e expiração.

JWT assina, não esconde. Não coloque senhas ou dados sensíveis no payload — qualquer um com o token consegue decodificá-lo.

Uso com go-jwt

Duas funções. Assinar e verificar.

package main

import (
	"fmt"
	"time"

	"github.com/bapadua-labs/go-jwt"
)

func main() {
	secret := "sua-chave-secreta-com-pelo-menos-32-bytes"

	claims := jwt.Claims{
		"sub": "usuario-123",
		"exp": time.Now().Add(24 * time.Hour).Unix(),
	}

	token, err := jwt.SignHS256(claims, secret)
	// ...

	parsed, err := jwt.VerifyHS256(token, secret)
	fmt.Println("subject:", parsed["sub"])
}

API

SignHS256(claims, secret)
Cria um token JWT assinado com HMAC-SHA256.
VerifyHS256(token, secret)
Valida assinatura, header (alg/typ) e expiração; devolve as claims.
Claims
map[string]interface{} — o payload do token.
HasValidExp() / IsExpired()
Helpers para inspecionar a claim exp.

Erros

ErrInvalidToken
Token malformado ou payload ilegível.
ErrInvalidSignature
Assinatura não confere ou secret incorreto.
ErrInvalidTokenType
alg diferente de HS256, ou typ presente e diferente de JWT.
ErrExpiredToken
exp ausente, inválido ou no passado.

Segurança

O que a lib faz

  • HMAC-SHA256 com comparação timing-safe
  • Base64 URL-safe (padrão JWT)
  • Valida header (alg = HS256; typ = JWT quando informado)
  • Rejeita tokens sem exp ou expirados

O que a lib ainda não faz

  • Validação de iss, aud, nbf
  • Algoritmos assimétricos (RS256, ES256…)
  • Revogação ou criptografia do payload
  • Use secrets fortes (mínimo recomendado: 32 bytes aleatórios).
  • Sempre defina exp com tempo de vida curto.
  • Transmita tokens apenas via HTTPS.
